# 设计：冰箱返鲜

## 功能规则
- 版本目标：Project Zomboid 42.20.4；运行时 Java 25；现有扩展框架 ZombieBuddy 2.3.2。
- 所有引擎识别的 fridge/freezer 容器在实际有电时适用，包括其中背包的食物。
- 对应游戏时间间隔内 `Age = max(0, Age - hours * FoodRotSpeedFactor / 24)`；沙盒档位 1..5 的倍率是 1.7、1.4、1、0.7、0.4。
- 不使用冷藏倍率或 frozen 状态降低返鲜速度。原有温度与冻结状态仍由游戏维护。
- Age 跨过原物品阈值自动改变新鲜/陈腐/变质；恢复到新鲜后继续恢复至零。
- 断电或移出时停止返鲜，之后由原版继续维护食物。只恢复年龄，不清除固有毒性或修改生熟状态。
- 单人本地计算；多人服务器唯一计算，客户端应用带版本与顺序信息的年龄快照。
- 以游戏时钟为准，暂停游戏或关闭服务器不按现实时间返鲜。

## 接入设计
- 在实际 `Food.updateAge(boolean)` 的 Age 写入点调整年龄积分，保留原版冻结、温度、lastAged 及阶段事件逻辑。
- 捕捉容器字段写入，移动前结清旧容器时间，移动后开始新容器时间；背包整体移动递归结算。
- 追踪世界冰箱生命周期并定时更新其中食品，不依赖原版活动物品列表覆盖全部食品。
- 原版 ItemStatsPacket 没有 Age；需要自定义服务器命令同步年龄、时间戳及物品定位。
- 供电时段必须分段记录，远处区块需根据可验证的原版市电/发电机时间补算，不能把返回时有电等同于过去全程有电。供电补算依据与测试记录在研究和验证文档。
- 游戏类转换严格检查目标方法及指令数量，版本或结构不匹配时停用返鲜并报告，不能半套接入运行。

## 交付与验证边界
- 交付源码、可复现构建脚本、Mod 安装包、中英说明和测试结果。
- 隔离验证使用独立缓存/配置，不覆盖现有游戏存档和设置。
- 单元测试和类转换通过不等于真实多人验收；最终说明逐层列出实际完成的验证。
